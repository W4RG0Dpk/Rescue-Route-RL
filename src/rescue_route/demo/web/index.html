How the recoverability shield works

  1. Observe. The UAV sees a 17×17 local map (7 channels: obstacles, no-fly zones, rooftops, its own position, the hospital, the current flood and the forecast flood probability) plus a 15-value state vector.
  2. Propose. A PPO policy (CNN encoder + LSTM memory) outputs a probability for each of 9 actions.
  3. Imagine. For every candidate action, the evaluator samples K plausible futures conditioned on the forecast: monotone flood masks with exactly the forecast's marginal probabilities, plus stochastic wind. It never sees the simulator's true future.
  4. Plan in each future. An exact time-expanded minimum-energy search checks whether the UAV can still deliver before the deadline, re-stabilise the payload, and then reach a dry base or rooftop with its battery reserve intact.
  5. Gate. P_unrec(s,a) = mean_k 1[M_rec^k < 0]. Actions with P_unrec ≤ δ are safe; the policy's favourite safe action is executed.
  6. Fall back. If no action meets δ, the least-risk action is taken. If even that has P_unrec ≥ ½ (confirmed with a larger sample), the UAV returns to base or lands on the nearest dry rooftop.

The flood model is a synthetic stochastic cellular automaton, not a hydrological model. The rainfall and wind processes were checked against ERA5 data (see the Weather tab).
